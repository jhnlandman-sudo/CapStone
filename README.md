# CapStone — Black-box optimisation (Imperial College PCMLAI)

Sequential maximisation of eight unknown functions (2 to 8 dimensions), one query per function
per round, using Gaussian-process surrogates, analytic local closures and deliberate
replicates. Every submitted query can be regenerated from the data and the seeded scripts in
this repository.

## Documentation

- **[Datasheet](docs/datasheet.md)** — the query history and function evaluations: motivation,
  composition, collection, preprocessing, uses, distribution and maintenance.
- **[Model card](docs/model_card.md)** — the optimisation approach: overview, intended use, how
  the strategy evolved over ten rounds, performance, assumptions and limitations, and ethical
  considerations.
- **[References](docs/references.md)** — each design decision mapped to its source and to the
  code that implements it.

## Repository layout

```
data/raw/initial/function_<i>/   supplied initial design (.npy), never edited
data/raw/portal/                 portal inputs.txt / outputs.txt, never edited
data/processed/                  function_<i>.csv and summary.csv, regenerated by src/build_dataset.py
src/build_dataset.py             raw -> processed, with shape and range checks
src/tune.py                      per-function GP kernel selection by 5-fold CV
src/validate_query.py            checks a round's queries against the portal format
rounds/weekNN/                   each round's query script (docstring = claim, evidence and
                                 prediction per function) and submitted queries
docs/                            datasheet, model card, references
```

## Reproduce

```bash
pip install -r requirements.txt
python src/build_dataset.py
python src/validate_query.py rounds/week10/Week10_queries.csv
```

The round scripts under `rounds/` are kept exactly as run. They read the history from a
`data_wN/` folder of per-function `.npy` arrays, which held the same rows as
`data/processed/` truncated to that round.
